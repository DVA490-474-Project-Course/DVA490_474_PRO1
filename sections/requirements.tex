\section{Requirement}
\label{section:requirement}

Requirements are necessary to establish in order to ensure that a satisfactory product can be produced and tested, ensuring it meets the original demands placed on the project. It is very important that clearly defined requirements exist from the onset of the project, reducing the chance of misinterpretations by the team and ensuring that the final product aligns with what the stakeholders envisioned. Additionally, it helps benchmark the system in a measurable way. This clearly shows the necessity for stakeholders involvement in establishing requirements to provide comprehensive and accurate requirements, which in turn helps minimize the amount of rework.

%===============================================================================
\subsection{Product requirements}
\label{subsection:product_requirements}

Product requirements entails the features, functionality and specifications which the final product must have to meet the demands of the stakeholders. The product requirements will serve as a blueprint for the development and design of the product that is to be delivered.

\subsubsection{Functional requirements}

Functional requirements describe the functions that the final product must have. The following functional requirements were established:
\begin{enumerate}[label*=\arabic*.]
    \item Robot
    \begin{enumerate}[label*=\arabic*.]
        \item Kick the ball towards designated target
        \item Pass the ball towards designated robot
        \item Keep control of the ball using the dribbler
        \item Block ball
        \item Move to designated target
        \item Omnidirectional (holonomic) movement
        \item Not crash into other robots
        \begin{itemize}
            \item Except if it is an attempt at trying to steal the ball from an opponent or to prevent opponents from scoring a goal
            \item Never acceptable if it causes any permanent damage on either robot
        \end{itemize}
        \item Not crash into the arena
        \item React accordingly to referee signals and commands (see\:\cite{robocup_small_size_league_rules_2024} for an explanation of the signals and commands)
        \begin{enumerate}[label*=\arabic*.]
            \item Halt
            \item Stop
            \item Normal start
            \item Force start
            \item Prepare kickoff
            \begin{enumerate}[label*=\arabic*.]
                \item Yellow team
                \item Blue team
            \end{enumerate}
            \item Perpare penalty
            \begin{enumerate}[label*=\arabic*.]
                \item Yellow team
                \item Blue team
            \end{enumerate}
            \item Direct free kick
            \begin{enumerate}[label*=\arabic*.]
                \item Yellow team
                \item Blue team
            \end{enumerate}
            \item Timeout
            \begin{enumerate}[label*=\arabic*.]
                \item Yellow team
                \item Blue team
            \end{enumerate}
            \item Ball placement
            \begin{enumerate}[label*=\arabic*.]
                \item Yellow team
                \item Blue team
            \end{enumerate}
        \end{enumerate}
        \item Send robot status information
        \item Hot-swap battery. The battery should be swappable by plugging in the robot to an alternative source and then changing the battery.
        \item Continuously monitor the capacity of the battery.
        \item Continuously monitor the temperature of the \ac{mcu}.
    \end{enumerate}
    \item Centralised strategic planner
    \begin{enumerate}[label*=\arabic*.]
        \item \ac{ai} functionality
        \item Swap field sides on demand
        \item Ensure actions for each robot is not taken from an individualistic point of view, but from a overarching team perspective with a strategic plan aimed at obtaining victory
    \end{enumerate}
    \item Simulation interface
    \begin{enumerate}[label*=\arabic*.]
        \item Send packages containing robot commands to grSim
    \end{enumerate}
    \item SSL interface
    \begin{enumerate}[label*=\arabic*.]
        \item Receive positional data from ssl-vision
        \item Receive referee commands from ssl-game-controller
        \begin{enumerate}[label*=\arabic*.]
            \item Have humanly operated referee functionality
            \item Have AutoReferee functionality
        \end{enumerate} 
    \end{enumerate}
    \item Communication protocol
    \begin{enumerate}[label*=\arabic*.]
        \item Be wireless
        \item Be peer-to-peer
        \item Ability to select between two carrier frequencies
    \end{enumerate}
    \item Hardware interface
    \begin{enumerate}[label*=\arabic*.]
        \item Control wheel motors
        \item Control kicker
        \item Control dribbler
        \item Provide sensor data
        \item Provide robot status information
    \end{enumerate}
\end{enumerate}

\subsubsection{Non-functional requirements}

Non-functional requirements describe the specifications of the deliverables in detail. The following non-functional requirements were established:
\begin{enumerate}[label*=\arabic*.]
    % Individual robot behaviour
    % Collective robot behaviour
    \item The centralised strategy planner must run on a central computer.
    \begin{enumerate}[label*=\arabic*.]
        \item A latency lower than $400\:\text{ms}$ from any point in time at which the centralised strategy planner gives a command until it starts executing on the robot.
    \end{enumerate}
    % Simulation
    \item Be able to simulate 12 robots.
    % Simulation interface
    % SSL interface
    % Communication
    \item Communication protocol
    \begin{enumerate}[label*=\arabic*.]
        \item Use WiFi
        \item Use Protobuf
        \item Use \ac{ros2} Humble
        \item $5\%$ dataloss or less
    \end{enumerate}
    % Hardware
    \item Each robot must have a reverse polarity protection circuit that changes polarity when the battery is connected incorrectly.
    \item Each robot must have a TVS-diode for over-voltage protection.
    % Wheels
    \item The robot must have four Swedish wheels.
    \item Maximum diameter of each wheel must be $70\:\text{mm}$.
    % Motor
    \item The size of each wheel motor has to be $43\:\text{mm}$ in diameter and $30\:\text{mm}$ in length.
    \item The weight of each motor for the wheels must be less than $200\:\text{g}$.
    \item Each motor must be capable of handling $24\:\text{V}$ ($6\:\text{S}$ battery).
    % Motor driver
    \item Each motor driver must work with an input voltage of $24\:\text{V}$ ($6\:\text{S}$ battery).
    \item The weight of each motor driver must be less than $200\:\text{g}$.
    % Dribbler
    \item Minimum \ac{rpm} for the dribbler motor is $10000\:\text{\ac{rpm}}$.
    \item Maximum length of the dribbler motor is $70\:\text{mm}$, excluding the mounting axles.
    % Kicker
    \item The solenoid (kicker) must be capable of launching the ball at a speed of at least $2\:\text{m/s}$.
    \item The solenoid must be capable of handling a voltage of at least $100\:\text{V}$. 
    \item The solenoid must have a diameter of less than $30\:\text{mm}$ and be less than $60\:\text{mm}$ in length, excluding plunger.
    % Battery
    \item The voltage of the battery in each robot must be $6\:\text{S}$ ($24\:\text{V}$ nominal).
    \item The robot must have battery capacity to continuously operate for $30\:\text{min}$.
    % Sensors
    \item For the break beam sensor, which detects if the ball is close to the dribbler, the beam cannot be smaller than $3\:\text{mm}$ in diameter.
    % Robot
    \item The robot must fit inside a cylinder which is $180\:\text{mm}$ in diameter and is $150\:\text{mm}$ tall.
    \item Maximum weight of the robot is $5\:\text{kg}$.
    \item The angle between the front wheels must be $120\degree$ and between the back wheels the angle must be $90\degree$.
    \item Minimum height of the middle plate is $80\:\text{mm}$.
    \item Screws with a uniform diameter must be used, with a minimum size of M3.
    %
    \item The robots \ac{mcu} must process input from sensors and control the motors in less than $40\:\text{ms}$.
    % SSL rules
    \item Comply with all \ac{ssl}-RoboCup rules, see\:\cite{robocup_small_size_league_rules_2024}.
    \item The vision pattern on the robot must follow the \ac{ssl} rules and fit on the top plate.
    \item The colour markings on top of the robot must comply with \ac{ssl} rules.
\end{enumerate}

\subsection{Project requirements}

The project has locked time and cost, focus will thus be placed on scope to ensure the project does not expand unrealistically, resulting in an inability to deliver the product. The following list describes what must be done in the project to be able to deliver the product:
\begin{itemize}
    \item Weekly meetings with both simulation and hardware teams to ensure alignment and progress tracking.
    \item Comprehensive documentation of all development activities, including hardware design, AI algorithms, simulation results, and testing outcomes.
    \item Participation in at least one international RoboCup-related event or competition during the project timeline to benchmark progress.
    \item Limit the project as described in Limitations, see section\:\ref{section:limiations}.
    \item Keep within budget, see Project budget, section\:\ref{section:project_budget}.
    \item Facilitate clear and good communication within the team, with sponsors and with stakeholders.
\end{itemize}
